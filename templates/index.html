Frontend-to-Backend REST API Blueprint

Since you are implementing the Django backend yourself, this page provides the exact endpoint schemas, HTTP methods, headers, and payload structures this UI expects. Toggle "Mode: Live Django REST API" anytime to connect this UI directly to your views!

POST /api/v1/auth/token/
Milestone 1 (JWT Login)

Authenticates user using email and password, returning access & refresh tokens.

// Request Body
{
  "email": "doctor@example.com",
  "password": "SecretPassword123"
}
// Response (200 OK); Django sets an HTTP-only session cookie
{ "user": { "id": 1, "email": "doctor@example.com" } }
GET / POST /api/v1/patients/
Phase 3 (Tenant Scoped)

Lists, searches, and creates patients. Organization context comes from the selected clinic in the authenticated session; record IDs outside that clinic return not found.

// POST payload; organization comes from the selected session clinic
{ "first_name": "", "last_name": "", "date_of_birth": "YYYY-MM-DD", "gender": "female", "phone": "", "primary_doctor_id": null }
GET / POST /api/v1/encounters/
Phase 3 (SOAP Notes)

Create, read, update, and delete structured SOAP encounters. Every patient and assigned doctor reference is validated against the selected clinic.

GET /api/v1/audit-logs/verify/
Milestone 5 (Hash-chain integrity)

Iterates the SHA-256 blocks for the tenant and verifies that every hash matches its preceding entry.
